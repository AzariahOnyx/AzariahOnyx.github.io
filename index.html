Information Architecture

The invisible design
that makes docs work.

Most technical writers ignore IA. I lead with it. Every system I build is architected before it's authored.

01
Reader Goal First
Navigation designed around what the reader wants to accomplish — not how the product team organized features.
02
Deterministic Terminology
Every concept has exactly one name. Synonyms are the primary cause of AI hallucinations and user confusion alike.
03
Tiered Architecture
Overviews → task guides → reference → troubleshooting, each with defined entry points and clear exit paths.
04
AI-Inhibition by Design
Structural elimination of vague phrasing ensures documents resolve predictably under AI retrieval.
05
Support-Driven Iteration
Documentation gaps live in support tickets. AI-assisted analysis surfaces problems that feed directly into the IA.
06
Scalable Taxonomy
Labeling and categorization systems that survive product growth and migrations without full restructures.

Documentation automation · Agent Skills

DocForge Skills — Source-grounded documentation workflow

A reusable, agent-assisted workflow that transforms an approved product specification into reviewable documentation. It separates source analysis, drafting, and proofing so claims remain traceable and unsupported details are surfaced instead of invented.

01Source intake02Analyzer03Evidence handover04Drafter05Coverage06Proofreader07Human approval

Capabilities: feature guides, task how-tos, release notes, and custom document profiles; classified claims and clarification questions; claim-coverage ledger; source-first QA; revision/change-impact handling; Python validation scripts and GitHub Actions checks.

Guardrails: unsupported claims are blocked, source quotations and hashes are checked by validators, and a structural PASS is not treated as publication approval. A human must verify technical behavior before release.

Knowledge quality · Retrieval evaluation

EMETIVRA — Knowledge Intelligence Studio

A local-first Markdown documentation auditing and reproducible keyword-retrieval benchmarking application. It helps compare how different chunking strategies and document structures affect ranked evidence for a fixed set of queries.

Workflow: audit a Markdown source, inspect recommendations, compare fixed and heading-aware chunks, annotate relevance manually, run a judged evaluation, inspect per-query ranked evidence, and export JSON/Markdown/CSV reports.

Scientific limitations: the retrieval engine is lexical BM25, not semantic or LLM-based RAG. The included v1.1 case study uses a synthetic corpus and mechanically generated labels; it is illustrative, not independent human validation or proof of production retrieval accuracy.
